1. Introduction about Camera Model

SG CUBE (Camera Model) is an intelligent, real-time multimodal assistive vision system designed primarily for visually impaired and blind individuals, while functioning simultaneously as a proactive, contextual AI desktop companion.

Traditional assistive technologies face a severe architectural trade-off: audio-only solutions lack spatial and visual grounding, whereas pure cloud-vision models suffer from bandwidth bottlenecks, high API latency, network drops, and critical privacy vulnerabilities. SG CUBE overcomes these limitations by deploying a hybrid Edge-Cloud architecture. Local high-speed perception engines (running deep CNN face detectors, ArcFace embeddings, spatial depth estimators, OCR, and currency classifiers) execute directly on the user's device with zero latency, while open-ended complex conversational understanding is orchestrated via a low-latency bidirectional WebSocket connection to Google Gemini Live.

Core Operating Philosophy: See. Understand. Remember. Assist.
SG CUBE continuously processes optical frames at 30 FPS, evaluates environmental hazards, recognizes familiar individuals, recalls personal user preferences from sub-millisecond RAM caches, and speaks natural voice alerts directly to the user.

3. Detailed Block Diagram Explanation

1. Sensory Input Stage

Captures raw physical signals from hardware. The optical sensor feeds 30 FPS video frames to the vision subsystem. Simultaneously, the microphone input operates with exclusive multi-thread arbitration, guaranteeing zero hardware lockups between the Windows background wake listener and the active Gemini voice session.

2. Preprocessing & Signal Conditioning

Standardizes video inputs to optimal processing resolutions ($640 imes 480$). It executes CLAHE (Contrast Limited Adaptive Histogram Equalization) across the luminance plane, eliminating harsh shadows and lighting shifts before neural feature extraction. Audio signals are passed through energy-based Voice Activity Detection (VAD) to filter ambient noise.

3. Local Edge Perception & Computer Vision Engines

  • Deep YuNet CNN Face Detector: Detects multi-scale faces under extreme yaw/pitch angles and harsh illumination ($<15 ext{ ms}$).
  • SFace ArcFace 128-D Extractor: Generates 128-dimensional L2-normalized cosine feature vectors for invariant biometric matching.
  • Spatial & Safety Analyzer: Computes optical variance, bounding box scales, and directional sectors to alert users to close obstacles, drop-offs, and hazards.
  • OCR & Currency Detector: Recognizes printed text from documents and labels, and identifies Indian Rupee banknotes (&8377;10 to &8377;500) with contour edge validation.

4. Intent Routing & Arbitration

The CommandRouter evaluates speech transcripts. If the request involves deterministic local knowledge (e.g., "Remember my meeting is at 3 PM", "Who is in front of me?", "What color is this?"), it routes directly to local engines with zero network latency. If open-ended semantic reasoning is required, audio/video frames are dispatched to Gemini Live.

5. High-Performance Local Persistence

Features a thread-safe in-memory RAM cache backed by SQLite WAL mode and FTS5 full-text indexing. Facts and preferences are cached in memory for sub-millisecond lookups ($0.028 ext{ ms}$), providing instant voice feedback without remote database dependencies.

6. Feedback & Actuation Stage

A prioritized response manager dispatches critical safety alerts (Priority 1) ahead of standard conversational turns (Priority 2) and environmental announcements (Priority 3). Audio is rendered smoothly through a single authoritative speaker queue.

4. System Methodology & Processing Pipeline

The camera model operates on a strict edge-first deterministic pipeline:

  1. Frame Quality Gating: Before running heavy inference, the system calculates Laplacian variance (blur), Michelson contrast, and exposure levels. Low-quality frames are rejected early to avoid false positive detections.
  2. Spatial-Temporal Tracking Cache: Rather than executing heavy 38 MB deep neural networks on every millisecond frame tick, a 150ms temporal cache monitors face bounding box centroid drift ($\Delta x, \Delta y < 25 ext{px}$). When a face is stationary, the identity is reused from cache, dropping frame latency from $15 ext{ ms}$ to $<0.2 ext{ ms}$ with 100% accuracy.
  3. Hierarchical 6-Tier Memory Search:
    1. Thread-Safe RAM Cache (<0.001 ms) → 2. Exact Indexed SQL (<0.1 ms) → 3. Normalized Alias → 4. SQLite FTS5 BM25 (<0.3 ms) → 5. Substring Match → 6. Gemini Live Cloud
  4. Local-First Persistence: When saving a memory ("Remember my favorite color is blue"), the database executes an atomic WAL transaction, immediately updates the RAM cache, and issues voice confirmation in $<11 ext{ ms}$ without waiting for remote server roundtrips.

6. Hardware & Software Requirements

Hardware Requirements

  • Processor (CPU): Intel Core i3 / AMD Ryzen 3 or higher (Intel Core i5 / Ryzen 5 recommended for multi-stream AI workloads).
  • System Memory (RAM): Minimum 4 GB RAM (8 GB recommended for optimal multi-threaded performance).
  • Storage Space: Minimum 500 MB free disk space for runtime binaries, ONNX neural models, and local databases.
  • Optical Camera: Standard USB Webcam, Integrated Laptop HD Webcam (720p / 1080p @ 30 FPS), or smart glasses camera bridge.
  • Audio System: Standard microphone array (with noise suppression) and integrated speakers or Bluetooth headset.

Software Requirements

  • Operating System: Windows 10 (64-bit) / Windows 11 (64-bit).
  • Programming Language: Python 3.10, 3.11, 3.12, or 3.13.
  • Computer Vision & AI: OpenCV 4.x / 5.x (with DNN ONNX inference module), NumPy, Pillow.
  • Audio & Speech: SpeechRecognition, PyAudio, sounddevice, standard-aifc, WebSockets.
  • Multimodal Cloud AI: Google Gen AI SDK (google-genai 2.18.1) for Gemini Live bidirectional streaming.
  • Database Engine: Native SQLite3 with FTS5 (Full-Text Search) virtual table support.
